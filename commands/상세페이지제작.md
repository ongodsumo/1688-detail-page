수입 상품의 상세페이지를 만든다. 입력은 둘 중 하나다.

- **1688 상품 URL** — 링크만 주어짐 (0단계부터)
- **이미지 폴더** — 공급처 이미지가 이미 폴더에 들어 있음 (1단계부터)

입력: $ARGUMENTS

---

## 시작 전 — 준비 확인

1. **스크립트 위치(SCRIPTS)를 정한다.** 이 플러그인의 `scripts/` 폴더다.
   - 먼저 `${CLAUDE_PLUGIN_ROOT}/scripts` 를 쓴다.
   - 그 경로가 치환되지 않았거나 없으면 플러그인 설치 폴더에서 찾는다.
     ```bash
     find ~/.claude/plugins -name fetch_1688_images.py 2>/dev/null
     ```
     찾은 파일이 든 폴더를 SCRIPTS로 쓴다. 아래 명령의 `"$SCRIPTS"`는 모두 이 경로다.
2. **파이썬 라이브러리가 있는지 확인한다.** 없으면 설치 명령을 보여주고 **설치해도 되는지 먼저 묻는다.**
   ```bash
   python -c "import requests, PIL, cv2, numpy, playwright; print('OK')"
   ```
   ```bash
   pip install requests Pillow playwright opencv-python numpy
   python -m playwright install chromium
   ```
   - 맥에서 `python`이 없으면 `python3`, `pip3`를 쓴다.
3. **작업 폴더를 정한다.** 사용자에게 상품 폴더를 어디에 만들지 묻는다 (기본값: 현재 폴더 아래 `상세페이지/<상품명>/`).
   이하 `<상품폴더>`라 부른다. 공급처 이미지는 `<상품폴더>/`에, 만든 결과물은 `<상품폴더>/output/`에 둔다.

## 0단계 — 1688에서 자산 수집 (링크로 시작할 때만)

브라우저 도구는 **Claude 데스크톱 앱의 내장 브라우저**(`mcp__Claude_Browser__*`)를 우선 쓴다.
없으면 Claude in Chrome(`mcp__claude-in-chrome__*`)으로 같은 절차를 밟는다.
둘 다 없으면 사용자에게 상품 페이지 이미지를 `<상품폴더>`에 직접 저장해 달라고 하고 1단계부터 시작한다.

1. 브라우저로 상품 URL을 연다.
   - **보안 확인(슬라이더 CAPTCHA)이 먼저 뜨는 경우가 많다.** 화면을 띄워 두고 사용자에게 밀어 달라고 요청한다. Claude는 CAPTCHA를 대신 풀지 않는다.
2. 페이지 텍스트로 **상품 속성표**를 읽는다 → 소재·중량(克重)·색상(颜色)·사이즈(尺码)·핏(版型)·소매(袖型)를 메모.
   - **브라우저가 페이지를 한국어로 자동번역했을 수 있다.** 그러면 한자 라벨로는 안 잡히고 오역이 섞인다(예: 사이즈 M이 "나"로 바뀜). 가능하면 번역을 끄고 원문으로 다시 읽는다. 번역된 채라면 라벨은 의미로 찾는다.
   - 속성표만 믿고 상품 유형·소재·사이즈를 정하지 않는다. **SKU 선택지(색상·사이즈 버튼)와 상세 이미지로 교차 확인**한다. 속성표는 공급처가 대충 채운 경우가 많다.
3. **로그인이 필요하면 사용자에게 요청한다.** 로그인 전에는 상세 본문이 잠겨 갤러리 9장만 보인다.
   - `https://login.1688.com/member/signin.htm` 으로 이동시켜 화면을 띄우고 QR 로그인을 부탁한다.
   - 계정·비밀번호는 절대 대신 입력하지 않는다.
4. 로그인 후 상품 페이지로 돌아가 **Shadow DOM에서 본문 이미지 URL을 수확**한다. 상세 본문은 `.html-description`의 shadowRoot 안에 있어 일반 `querySelectorAll('img')`로는 안 잡힌다.
   ```js
   const host = document.querySelector('.html-description');
   const re = /https?:\/\/[^"'\s)]+?\.(?:jpg|jpeg|png|gif|webp)[^"'\s)]*/gi;
   JSON.stringify([...new Set(host.shadowRoot.innerHTML.match(re))])
   ```
   **상단 갤러리는 방식이 다르다.** shadowRoot가 아니라 일반 `img`이고, 주소 끝에 썸네일 접미사(`.jpg_.webp`, `.jpg_100x100.jpg` 등)가 붙어 있다.
   ```js
   const urls = [...document.querySelectorAll('img')].map(i => i.src)
     .filter(s => s.includes('alicdn.com/img/ibank/'))
     .map(s => s.replace(/(\.(?:jpe?g|png|gif))_.*$/i, '$1'));   // 썸네일 접미사를 떼면 원본
   JSON.stringify([...new Set(urls)])
   ```
   - 상점 로고·추천상품 썸네일이 섞여 나올 수 있다. 그대로 받아도 1단계 점검에서 걸러진다.
   - 갤러리는 `--prefix 갤러리`로 따로 받는다.
5. URL을 텍스트 파일(한 줄에 하나)로 저장하고 내려받는다. 스크립트도 썸네일 접미사를 한 번 더 떼고 받는다.
   ```bash
   python "$SCRIPTS/fetch_1688_images.py" urls.txt "<상품폴더>" --prefix 본문
   ```

**함정**
- 브라우저 패널이 숨겨져 있으면 `setTimeout` 기반 스크립트가 타임아웃으로 죽는다. 탭을 앞에 띄우고, 스크롤은 대기 없이 한 번씩 나눠 실행한다.
- 페이지 하단 "热门推荐/搭配组货"의 이미지는 **다른 상품 홍보 배너**다. 상세 본문 구간(`商品详情` ~ `搭配组货`) 밖의 것은 버리거나 `_다른상품_추천배너/`로 분리한다.

## 1단계 — 자산 점검 (건너뛰면 나중에 다 뒤집는다)

**`detail-asset-auditor` 에이전트에게 위임한다.** 소스 이미지가 50장 안팎이라
직접 열면 대화 문맥이 이미지로 가득 찬다. 에이전트가 매니페스트만 돌려주므로 그 표를 근거로 2단계를 쓴다.
프롬프트에 이미지 폴더 절대경로를 넣어 호출하고, 돌아온 매니페스트는 요약하지 말고 **그대로 사용자에게 보여준다.**

에이전트가 하는 일(직접 할 때의 절차이기도 하다):

1. 전체 파일 크기를 한 번에 확인한다.
2. **GIF도 반드시 열어본다.** 1688 GIF는 애니메이션이 아니라 *단일 프레임 사진*인 경우가 많다. 확장자만 보고 건너뛰면 제일 좋은 착용컷을 놓친다.
3. 이미지를 실제로 열어 분류한다: **히어로 / 원단 매크로 / 디테일 / 착용컷 / 컬러 플랫 / 사이즈 실측표**.
   - 사이즈 실측표는 본문 중반에 이미지로 박혀 있는 경우가 많다. 찾으면 표를 HTML로 옮겨 적는다.
4. **오염 요소를 목록으로 만들어 사용자에게 알린다.**
   - 중국어 문구 / 공장 상호·워터마크
   - 브랜드 로고, 행택
   - 좌우에 붙은 컬러칩 띠
   - 모델이 착용한 **타 브랜드 소품**(비니·신발 로고) → 컷은 그대로 써도 되지만, 어느 컷에 어떤 브랜드가
     보이는지 **참고사항으로 알린다.** 단 **대표이미지에는 쓰지 않는다** —
     스마트스토어가 대표이미지의 타 브랜드 로고 노출을 제한한다.
   - → 오염 요소마다 아래 표의 **세 가지 처리 중 하나**로 분류해 보고한다. 에이전트는 읽기 전용이라 **대상·위치(%)·처리 방법만 돌려주고, 실제로 지우는 건 메인 세션**이 한다.
5. 컬러 개수·사이즈 범위를 확정한다.

**오염 요소 지우기** — `erase_region.py` (메인 세션이 실행)

| 상황 | 처리 |
|---|---|
| 흰 배경 위에 **떨어져 있는** 로고·문구·칩 (모서리 배너 등) | `--fill auto` 로 직접 지운다. 티가 안 난다 |
| 무늬 있는 배경 위, 주변과 비슷한 톤 | inpaint(기본값). 결과를 확대해 확인할 것 |
| **제품·인물에 겹친** 로고·행택·칩 | 직접 지우지 말 것. 사각형으로 채우면 옷을 베어먹고 inpaint는 뭉갠다 → **포토샵 생성형 채우기를 부탁**하거나 그 부분을 크롭으로 피한다 |

```bash
python "$SCRIPTS/erase_region.py" 원본.jpg --box left,top,width,height --fill auto   # %단위, 여러 번 가능
```
- 원본은 보존되고 `_clean` 파일로 저장된다. 덮어쓰려면 `--inplace`.
- 지운 뒤에는 반드시 그 부위를 확대해 열어본다.

## 2단계 — 상세페이지 HTML 작성

**뼈대는 처음부터 쓰지 않는다.** 플러그인의 `templates/detail_template.html`을
`<상품폴더>/output/상세페이지_YYYY-MM-DD.html`로 복사해서 채운다.

**섹션 구성** — 히어로 → 스펙 → 원단/기술 → 디테일 3종 → 사용 장면 → 스타일링 → 컬러 → 사이즈표 → 구매 전 안내
(상품에 맞지 않는 섹션은 지운다. 섹션은 반드시 `.page` 바로 아래 `<section>`으로 둔다 — 3단계 추출기가 이 경계에서 이미지를 자른다.)

**카피는 `detail-page-copywriter` 에이전트에게 먼저 받는다.** 레이아웃 계산과 문구 창작은 성격이
다른 일이라 나눈다. 1단계 매니페스트의 스펙과 섹션 구성을 프롬프트에 담아 호출하고,
돌아온 후보 중 골라 HTML에 심는다. 자료에 없는 성능을 지어내지 않았는지 반드시 대조한다.

**규칙**
- 폭 860px 단일 칼럼, Pretendard, `word-break:keep-all`, 숫자에 `font-variant-numeric:tabular-nums`
- 공급처 이미지는 자르지 말고 **CSS 크롭**으로 영역만 쓴다. 값은 인라인 스타일로 통일한다(클래스와 나눠 적으면 한쪽만 갱신되는 사고가 난다).
  - 로고·문구를 배제해야 할 때: `background-size:NNN% auto` + `background-position` 으로 창 시작점을 직접 지정
  - 깨끗한 사진: `background-size:cover`
  - 담을 내용의 가로세로비와 프레임 비율이 어긋나면 위치를 아무리 바꿔도 잘린다 → `aspect-ratio`를 내용에 맞춘다
- **브랜드명 표기 여부는 사용자에게 묻는다.** 무브랜드로 판매한다면 본문·푸터에 브랜드명을 넣지 않는다.
- **AI로 생성한 이미지를 쓰면 하단에 작은 글씨로 반드시 명시한다.**
  캡션: `AI로 생성한 연출 이미지입니다. 실제 제품 촬영본이 아니며 …`
  구매 전 안내의 '이미지' 항목에도 한 줄 남긴다. "연출 컷입니다"만으로는 부족하다 —
  생성 이미지라는 사실 자체를 밝혀야 한다
- 카피는 소비자 언어로: 中空섬유→**에어포켓**, 썸홀→**엄지홀**, 발라클라바→**바라클라바**, 파일 소재→**긴 털**,
  요크→**메쉬 패널**, 어깨선→**어깨 봉제선**(그냥 "어깨선"은 옷의 어깨 라인인지 봉제선인지 모호하다)
  - 판단 기준: **파는 사람이 물어봐야 아는 말이면 사는 사람은 더 모른다.**
  - 용어를 하나 바꾸면 **페이지 전체를 훑어 같이 맞춘다.** 소제목만 고치면 같은 것을 두 이름으로 부르게 된다.
- 모바일에서 카드 그리드는 **열 수를 유지**하고 여백·글자만 줄인다. 단, 전신 착용컷 3열은 너무 작으니 2열로 접는다.
- **템플릿은 의류 기준이다.** 용품(가방·조끼·캠핑용품 등)이면 템플릿 각 섹션 주석의 「자료 없을 때」 처리법을 따른다 — 원단·스타일링 섹션 삭제, 사이즈표 열 교체, 컬러 1색 버전 등.
- **섹션 하나가 너무 길면 둘로 나눈다.** 추출기는 섹션 단위로 이미지를 자르므로, 디테일 행이 4개 이상이면 `<section>`을 둘로 쪼갠다(모바일에서 한 장이 7,000px을 넘는 일이 생긴다).
- 스펙 스트립은 **3칸**으로 맞춘다. 카피가 4개 오면 하나를 고르거나 원단·디테일 섹션으로 옮긴다.

## 3단계 — 이미지 추출 & 눈으로 검수 (반복)

```bash
python "$SCRIPTS/html_to_images.py" "<html경로>" --mobile --width 1000   # 실제 업로드용
python "$SCRIPTS/html_to_images.py" "<html경로>"                          # PC 확인용 860px
```

- 결과는 HTML과 같은 폴더의 `images/<HTML파일명>_mobile/`에 `상세_01.jpg …`로 저장된다.
- 스마트스토어는 이미지 한 장으로 PC·모바일을 함께 쓰므로 **모바일 레이아웃 + 1000px**이 최종본이다.
- 추출 후 **반드시 이미지를 열어서 본다.** 정렬 어긋남·크롭 실수는 코드만 봐서는 안 보인다.
- 추출과 검수는 **`detail-page-reviewer` 에이전트에게 위임한다.** 프롬프트에 HTML 절대경로와 SCRIPTS 경로를 넣는다.
  결함 목록을 받아 이쪽에서 고치고, 고친 뒤 다시 호출해 재검수한다. "이상 없음"이 될 때까지 반복한다.
  마지막 한 번은 직접 눈으로 확인한다 — 취향·톤 판단은 에이전트가 하지 않는다.
- 자주 나오는 수정: 크기 다른 텍스트의 밑선 정렬(`height` 고정 + `align-items:flex-end`), 칸 간격은 각 칸 패딩이 아니라 `gap`으로, 모바일 글자 크기.

## 5단계 — 대표이미지

```bash
python "$SCRIPTS/make_thumbnail.py" 원본.jpg "<상품폴더>/output/대표이미지/대표_1_설명_YYYY-MM-DD.jpg" --box left,top,size
```

- `--box`는 **% 단위**다(erase_region.py·자산 점검 매니페스트와 같다). left·size는 원본 가로 기준, top은 세로 기준. 생략하면 가운데 정사각.
- 1000×1000, **텍스트·로고 없음**
- 3종을 만들어 고르게 한다: ① 단품 플랫 ② 착용컷 ③ 임팩트 컷
- 추천은 **단품 플랫을 대표**로 — 검색결과에서 형태가 0.5초 안에 읽혀야 클릭이 된다
- 원본이 1000px보다 작으면 업스케일 경고가 뜬다. 가능하면 고해상도 원본을 다시 받는다.

## 6단계 — 마무리

**결과물 경로를 바로 열 수 있게 안내한다.** 제작이든 수정이든 작업을 끝낼 때마다 빠뜨리지 말 것.
- 폴더 여는 명령을 bash 코드 블록으로 준다. 경로에 공백이 있을 수 있으니 큰따옴표로 감싼다.
  - 윈도우: `explorer "<상품폴더>\output"` / 맥: `open "<상품폴더>/output"`
- 이어서 **업로드용이 어느 폴더의 몇 장인지** 한 줄로 짚는다 (모바일 1000px 상세 N장 / 대표이미지 폴더)
- 폴더가 여럿이면 표로 — 업로드용 · 대표이미지 · 원본 HTML · PC 확인용 순서로
- 소스 이미지는 **삭제하지 않는다.**

| 단계 | 방식 |
|---|---|
| 0 · 1688 수집 | 메인 세션 (브라우저 조작) |
| **1 · 자산 점검** | **`detail-asset-auditor` 에이전트** |

| 4~6 | 메인 세션 |

에이전트로 뗀 단계는 **이미지를 대량으로 열어보는 단계**다. 메인 문맥에 이미지가 쌓이지 않게 분리하는 것이 목적이다.

**에이전트에 넘길 때 반드시 프롬프트에 담을 것**
- 이미지 폴더 / HTML 파일 / SCRIPTS의 **절대경로**
- 이 상품이 무엇인지 한 줄 (예: "와플 조직 후드티, 4색, S~XL")
- 무브랜드 판매 여부 등 판단 기준

서브에이전트는 문맥을 공유하지 않는다. 앞 단계에서 정한 크롭 값이나 용어 결정은
**프롬프트에 명시적으로 적어 넘겨야** 한다.
